## 二、逐题分析

### M. Minimum Records（AC，09:46:13，1 次 TL）

**知识点推测**：区间最值 + 二分 + DP + 线段树/ST 表。从代码看，题目涉及 `al[i]`、`ar[i]` 两个数组，需要从右往左 DP，每次二分找到满足 `max(al[i+1..mid]) <= ar[i]` 的最远 `mid`，然后查询 `dp[i+1..mid+1]` 的最小值。

**时间线**：
- 09:39 首次提交，TL（983ms / 1s），使用两棵线段树（T1 维护 dp 最小值，T2 维护 `-al` 的最大值）。
- 09:46 改用 ST 表维护 `al` 的区间最大值 + 一棵线段树维护 dp，AC（388ms）。

**关键分析**：

首次代码的核心问题在于**常数**：

```cpp
struct sgt{
    int tr[N<<2];
    void mdf(...) { ... }
    int get(...) { ... }
}T1, T2;
```

两棵 `N<<2` 的线段树，每棵树在 1e6 数据下递归查询/修改，常数约为 ST 表的 2–3 倍。983ms 已经非常接近 1s 时限，属于"运气不好就 TL"的边缘状态。

第二次提交将 `al` 的区间最大值查询改为 ST 表（O(1) 查询），只保留一棵线段树维护 dp，时间降到 388ms，余量充足。

**改进点**：在 1e6 数据 + 1s 时限的题目中，应优先评估常数。ST 表在"静态区间最值"场景下几乎总是优于线段树，且代码更短。建议形成"看到静态区间最值 → 先想 ST 表"的条件反射。

### D. Duel of Wrath（AC，09:53:13，2 次 WA）

**知识点推测**：数学/贪心 + 大数处理。从代码看，题目给定 `a, b, A, B`，需要计算某个 `k`（满足 `k*a >= B` 的最小 `k` 附近），然后判断 `A - k*b - 4*b <= 0` 是否成立。

**时间线**：
- 09:43 首次提交，WA（`int` 版本）。
- 09:48 第二次提交，WA（改为 `long long`，但 `k*a` 和 `k*b` 仍可能溢出）。
- 09:53 第三次提交，AC（改用 `__int128`）。

**关键分析**：

三次提交的代码差异非常小，核心变化是数据类型：

```cpp
// 第一次：int
int a,b,A,B;
int k = B/a-3;

// 第二次：long long
#define int long long
int k = B/a-3;

// 第三次：__int128
__int128 a,b,A,B;
int k = B/a-3;
while(k*a < B)k++;
```

问题在于：`k` 的量级约为 `B/a`，而 `k*a` 和 `k*b` 可能达到 `B` 的量级。如果 `B` 接近 `1e18`，`k*a` 在 `long long` 下仍可能溢出（`k` 本身是 `long long`，`k*a` 的乘积可能超过 `9e18`）。第三次用 `__int128` 彻底解决。

**改进点**：
- **数据范围先行**：拿到题目第一件事是看数据范围，确定是否需要 `long long` / `__int128`。本题两次 WA 都是因为"先写再改"，浪费了 40 分钟罚时。
- **乘法溢出检查**：当代码中出现 `k*a`、`k*b` 这类"两个变量相乘"时，应主动检查乘积上界。一个实用技巧是：在本地用极限数据（如 `a=1, B=1e18`）跑一遍，看是否溢出。

### C. Counting Arrays（AC，10:12:32，0 次错误）

**知识点推测**：组合计数 + DP + 前缀和优化。从代码看，题目涉及 `p[i]`（位置）和 `v[i]`（值）的约束，需要计算满足某些条件的数组个数，模 998244353。代码中有一个预处理 `dp[d][j][r]`（三维 DP，`d` 是段长，`j` 是增量，`r` 是剩余值），以及一个 `f[i][j]` 的滚动 DP。

**时间线**：10:12 一次通过。

**关键分析**：

这是一道**实现难度较高**的计数题（三维预处理 + 滚动 DP + 模运算），能一次通过说明对组合计数的套路比较熟悉。代码中的 `gmod` 函数（`if(x>=mod) x-=mod`）和 `1ll*...%mod` 的写法比较规范。

这里用两个 `while` 动态调整 `L` 和 `R` 的范围，避免了每次从 0 开始枚举，是一个不错的常数优化。

### K. Keep Your Distance（AC，10:21:12，0 次错误）

**知识点推测**：二分答案 + 区间约束可行性判定。从代码看，题目给定 `a[i]`（目标位置）和 `dis[i]`（相邻距离约束），需要判断是否存在一组位置 `x[i]` 使得 `|x[i] - a[i]| <= lim` 且 `|x[i] - x[i-1]| <= dis[i]`，二分最小的 `lim`。

**时间线**：10:21 一次通过。

**关键分析**：

`check` 函数的核心是维护当前可行区间 `[mn, mx]`：

```cpp
int mn=a[1]-lim, mx=a[1]+lim;
for(int i=2; i<=n; ++i){
    int lb=mx-dis[i], rb=mn+dis[i];
    int cl=a[i]-lim, cr=a[i]+lim;
    if(lb<cl&&rb>cr) return false;
    if(lb<cl){ mx=cr; mn=max(rb, cl); continue; }
    if(rb>cr){ mn=cl; mx=min(lb, cr); continue; }
    mn=cl; mx=cr;
}
```

这段代码的逻辑是：将前一个区间的可行范围 `[mn, mx]` 通过距离约束 `dis[i]` 映射到当前点的可行范围 `[mx-dis[i], mn+dis[i]]`，再与 `[a[i]-lim, a[i]+lim]` 求交。三个分支分别处理"左边界被裁剪"、"右边界被裁剪"、"完全包含"的情况。

**潜在风险**：`if(lb<cl&&rb>cr) return false;` 这个判断在 `lb >= cl` 且 `rb <= cr` 时不会触发，但此时区间 `[lb, rb]` 可能为空（`lb > rb`）。不过由于 `lb = mx - dis[i]`、`rb = mn + dis[i]`，且 `mn <= mx`，所以 `lb <= rb` 恒成立（因为 `mx - dis <= mn + dis` 等价于 `mx - mn <= 2*dis`，而 `mx - mn` 是前一个区间的宽度，在合法状态下应满足此约束）。这个不变量需要仔细维护，本题一次通过说明实现是正确的。

**改进点**：本题没有明显失误。二分上界 `2e9` 是合理的（`a[i]` 的范围推测在 `1e9` 量级），但可以更精确地设为 `max(|a[i] - a[1]|) + sum(dis)` 的上界，不过 `2e9` 已经足够。

### I. Invisible Edges（AC，10:56:20，0 次错误）

**知识点推测**：图论 + 构造。从代码看，题目有两个子任务（通过首字符 `'c'` 区分）：
- 子任务 1（`solvec`）：给定一棵树，给每个点赋一个值 `a[u]`，使得某种性质成立（DFS 序构造）。
- 子任务 2（`solved`）：给定 `b[i]`，构造一组边，使得每个点的"深度"或"排名"满足 `b[i]`。

**时间线**：10:56 一次通过。

**关键分析**：

子任务 2 的核心是用栈模拟：

```cpp
sort(id+1,id+n+1,cmp);  // 按 b[i] 排序
for(int t=1;t<=n;t++){
    int i = id[t];
    if(t == 1){ st.push(i); continue; }
    int k = b[i] - b[id[t-1]];
    for(int j=1;j<=k-1;j++) st.pop();
    int u = 0;
    if(!st.empty())u = st.top();
    add(u,i);
    st.push(i);
}
```

这段代码的逻辑是：按 `b` 值从小到大处理，相邻两个点的 `b` 差值 `k` 决定了需要弹出多少个栈元素（`k-1` 个），然后当前点的父节点是栈顶。这是一个经典的"用栈构造树"的套路。

**潜在风险**：`for(int j=1;j<=k-1;j++) st.pop();` 中如果 `k` 很大而栈不够深，会弹出空栈（UB）。但题目保证有解，所以 `k` 不会超过当前栈深。一次通过说明对题目约束的理解是正确的。

**改进点**：本题没有明显失误。代码中 `ans[0].size()` 返回 `size_t`，`printf("%d", ...)` 会有警告，但实际不影响（`size_t` 在 64 位下是 8 字节，`%d` 读 4 字节，小数据下低 4 字节正确）。建议养成 `printf("%zu", ...)` 或强制转换的习惯。

### E. Enclose the Point（AC，13:03:15，2 次错误：WA + RE）

**知识点推测**：计算几何 + 凸包 + 点定位。题目给定 `n` 个点，`q` 次询问，每次给定一个点 `u`，要求输出一个包含 `u` 的三角形（或四边形）的顶点编号，若不存在输出 `-1`。

**时间线**：
- 12:39 首次提交，WA。
- 12:49 第二次提交，RE（`assert(0)` 触发）。
- 13:03 第三次提交，AC。

**关键分析**：

这是一道**实现复杂度很高**的几何题，代码量约 200 行，涉及凸包（Andrew 算法）、点在凸多边形内判定、三角形包含判定、极角排序 + 二分查找等。

**第一次 WA 的原因**（从代码推断）：

首次代码在凸包大小 `> 4` 的分支中，使用了 `lower_bound(CC.begin(), CC.end(), u, cmp)` 来定位 `u` 在极角排序中的位置，但没有处理 `v == CC.size()` 的情况（即 `u` 的极角大于所有 `CC` 中的点）。此时 `CC[v]` 越界访问，导致未定义行为。

**第二次 RE 的原因**：

第二次提交在 `> 4` 分支的末尾保留了 `assert(0)`：

```cpp
assert(0);
```

当所有 `if` 分支都未命中时（即 `u` 不在任何候选三角形中），程序触发 `assert` 并 abort。这说明**点定位的逻辑有遗漏**——某些情况下 `u` 确实在凸包内，但四个候选三角形都无法覆盖它。

**第三次 AC 的修正**：

```cpp
if(v == CC.size()){
    printf("-1\n");
    continue;
}
```

增加了对 `v == CC.size()` 的处理（输出 `-1`），并将 `assert(0)` 替换为 `printf("-1\n")`。同时，`pr` 的计算从 `CC[v+1]` 改为 `if(v+1 == CC.size()) pr = C[tp]; else pr = CC[v+1];`，修正了边界。

**关键教训**：

1. **`lower_bound` 的返回值必须检查是否等于 `end()`**。这是 C++ STL 的经典陷阱，尤其在几何题中（极角排序后查询）非常常见。
2. **`assert(0)` 不能作为"兜底逻辑"**。`assert` 的语义是"此处不可能到达"，如果实际可能到达，说明逻辑有漏洞，应该输出合理的默认值（如 `-1`）而不是 abort。
3. **调试输出残留**：第一次提交中有 `printf("i = %lld,tp = ...")` 这样的调试语句，虽然不影响正确性（输出到 stdout 会干扰评测），但说明提交前没有清理代码。建议养成"提交前删除所有调试输出"的习惯。

**改进点**：
- 几何题的边界情况（点在凸包顶点上、点在凸包边上、极角恰好相等）需要系统性地枚举测试。
- 建议写一个暴力对拍程序（`n <= 10` 时枚举所有三角形），在本地验证。

**建议**：补题时记录"从读题到想出思路"的完整思考过程，找出卡点。如果是"没想到某个定理"，就把定理记下来；如果是"想到了但不敢写"，就分析为什么不敢写（是复杂度不确定，还是实现没把握）。

## 四、失误与改进建议

### 4.1 具体失误清单

| 题目 | 失误类型 | 具体表现 | 影响 |
|------|----------|----------|------|
| M | 常数评估不足 | 双线段树在 1e6 数据下 TL（983ms/1s） | +20 min 罚时 |
| D | 数据范围疏忽 | `int` → `long long` → `__int128` 三次迭代 | +40 min 罚时 |
| E | 边界处理遗漏 | `lower_bound` 返回 `end()` 未检查，越界 WA | +20 min 罚时 |
| E | 调试残留 | 提交代码中含 `assert(0)` 和 `printf` 调试语句 | +20 min 罚时（RE） |
| E | 兜底逻辑错误 | 用 `assert(0)` 代替 `-1` 输出 | 同上 |
| 全局 | 后半程空窗 | 13:03–14:15 无比赛内提交 | 错失 1–2 题 |

### 4.2 技术改进建议

1. **数据范围检查清单**：每次写代码前，先列出所有可能溢出的表达式（乘法、累加、位移），确定数据类型。建议在代码模板中加入 `#define int long long` 的注释提醒，或使用 `__int128` 的宏。

2. **STL 边界检查**：`lower_bound` / `upper_bound` 的返回值必须与 `end()` 比较。建议写一个辅助函数：
   ```cpp
   template<typename T>
   int safe_lb(const vector<T>& v, const T& x) {
       auto it = lower_bound(v.begin(), v.end(), x);
       return it == v.end() ? -1 : it - v.begin();
   }
   ```

3. **提交前检查清单**：
   - 删除所有 `printf` / `cout` 调试输出（除非是交互题）。
   - 删除所有 `assert`（或确认 `assert` 的条件恒成立）。
   - 检查数组大小是否足够（尤其是 `N<<2`、`N*N` 等）。
   - 检查多组数据是否清空了全局变量。

4. **几何题对拍**：对于计算几何题，建议写一个 `n <= 10` 的暴力程序，随机生成数据对拍。这能发现大部分边界问题（点在边上、共线、重合等）。

### 4.3 策略改进建议

1. **时间盒机制**：对每道题设定时间盒（如简单题 20 分钟、中等题 45 分钟、难题 60 分钟）。超时后强制切换，避免"卡题"导致后半程空窗。本场 E 题从 12:39 到 13:03 花了 24 分钟调试，虽然最终 AC，但挤占了 A 题的时间。如果 E 题在 12:50 仍未 AC，应考虑暂时搁置，先看 A 题。

2. **罚时意识**：D 题的两次 WA 完全是"可以避免"的。建议在提交前问自己三个问题：
   - 数据范围是否覆盖了所有情况？
   - 边界条件（`n=1`、`n=0`、全相同、全不同）是否考虑？
   - 是否有溢出风险？

3. **后半程策略**：13:03 之后有 72 分钟，应该至少尝试 1–2 道题。建议在比赛中期（约 2.5 小时）做一次"题目盘点"，确定哪些题有思路、哪些题完全没思路，优先推进"有思路但未实现"的题目。

4. **团队协作**：虽然只有一台电脑，但另外两名队员应持续读题、思考。建议在比赛开始 30 分钟内完成"全题扫描"，标记每道题的难度和可能方向，避免后期"不知道做什么"。

### 4.4 一句话结语

本场比赛的算法能力是够的（6 题 + 赛后 3 题），但**细节把控**和**时间管理**是明显的短板——D 的溢出、M 的常数、E 的调试残留，每一处都消耗了宝贵的罚时和比赛窗口。如果能把"提交前检查"变成肌肉记忆，把"时间盒"变成习惯，下次比赛的成绩有望从 6 题提升到 8 题以上。加油！
