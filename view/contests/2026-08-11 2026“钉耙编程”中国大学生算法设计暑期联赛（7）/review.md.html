二、逐题分析

B. 今晚吃……（AC，罚时 35 min）

知识点：动态规划、状态压缩、字符串处理

难度预估：中等偏易（签到题级别）

题目分析：给定一个 01 字符串，需要选取一个子序列，使得该子序列包含的所有长度为 2 的子串集合与原字符串完全相同。求子序列的最小长度。

解题思路：观察到长度为 2 的子串只有 4 种可能（00、01、10、11），可以用 4 位二进制掩码表示需要覆盖的子串集合。设 dp[i][j][mask] 表示考虑到原串第 i 个字符，子序列最后一个字符为 j，已覆盖的子串集合为 mask 时的最小长度。转移时可以选择跳过当前字符或将其加入子序列。

提交记录分析：

  • 提交 #1（WA）：首次提交的代码中，转移时使用了 nmac=(1<<(b+c*2))，其中 b 是上一个字符，c 是当前字符。但这里 b 是 a[t]（原串第 t 个字符），而不是子序列中上一个字符。正确的做法应该使用 i（子序列中上一个字符）来计算新掩码。这是一个典型的状态转移错误——混淆了原串位置和子序列状态。

    关键错误代码：

    gmin(dp[t+1][c][mac | nmac],x+1);  // 错误：nmac 使用了 a[t] 而非 i

    正确代码：

    gmin(dp[t+1][c][mac | (1<<(i+c*2))],x+1);  // 正确：使用子序列上一个字符 i

  • 提交 #2（AC）：修正了上述错误后一次通过。

经验教训：在 DP 中，转移时使用的"上一个状态"必须严格来自 DP 状态本身，而不是原数据。这类错误在比赛中很常见，需要仔细检查状态定义和转移方程的一致性。

H. 今晚吃 NPC（AC，罚时 21 min）

知识点：位运算、构造

难度预估：简单

题目分析：给定一个由 &、^、| 组成的表达式，需要构造一组非负整数解使得表达式结果等于 w。

解题思路：按位独立考虑。对于每一位，可以构造 x1 = w，其余变量根据运算符选择 0 或全 1，使得表达式结果恰好为 w。具体地：

  • 如果运算符是 | 或 ^，令后续变量为 0，不影响结果；
  • 如果运算符是 &，令后续变量为全 1（0x7FFFFFFF），不影响结果。

提交记录分析：一次 AC，代码简洁高效。这是本场比赛最顺利的一题。

经验教训：构造类题目往往有非常简单的解法，不要想复杂。按位独立分析是处理位运算问题的常用技巧。

L. 今晚吃 TopTree（AC，罚时 42 min）

知识点：树形 DP、贪心、优先队列

难度预估：中等

题目分析：给定一棵有根树，可以执行操作将节点的两个儿子合并到一个新节点下。需要分别最小化最终树的高度和原始节点的深度和。

解题思路：

  • 最小化高度：对每个节点，将其儿子的高度排序，每次合并两个高度最小的儿子，可以使得最终高度最小。用优先队列维护。
  • 最小化深度和：对每个节点，将其儿子的子树大小排序，每次合并两个子树大小最小的儿子，可以使得原始节点的深度和最小。同样用优先队列维护。

提交记录分析：一次 AC。代码实现清晰，使用两个优先队列分别维护高度和子树大小。

经验教训：树形结构上的贪心问题，关键是找到正确的贪心策略。本题中"每次合并最小的两个"是经典策略，需要熟练掌握。

I. 今晚吃草莓（AC，罚时 70 min）

知识点：动态规划、单调队列优化、滚动数组

难度预估：中等

题目分析：给定 n 个位置和 m 次冲刺，每次冲刺可以选择位移 d（|d| ≤ k_i），撞墙或 |d| = k_i 时获得草莓。求从起点 s 出发，经过 m 次冲刺到达终点 t，且总草莓数不超过 K_t 时的最大撞墙次数。

解题思路：设 dp[i][j][k] 表示前 i 次冲刺后位于位置 j，撞墙 k 次的最小草莓数。转移分为三种情况：

  1. 选择位移 ±k_i（必然获得草莓）；
  2. 选择位移导致撞墙（必然获得草莓）；
  3. 选择其他位移（不获得草莓），可以用单调队列优化区间最小值转移。

提交记录分析：

  • 提交 #9（MLE）：使用 dp[N][N][N] 三维数组（N=550），内存占用约 530MB，超出限制。这是典型的内存超限问题。

    关键错误代码：

    int dp[N][N][N];  // 550 * 550 * 550 * 8 bytes ≈ 1.3GB

    实际上代码中声明的是 dp[N][N][N] 其中 N=550，但 long long 类型导致内存更大。

  • 提交 #10（AC）：改为滚动数组 dp[2][N][N]，将内存从 530MB 降至约 5MB。同时使用单调队列优化区间最小值转移，时间复杂度 O(n²m)。

经验教训：

  1. 三维 DP 数组在 n、m 较大时极易 MLE，应优先考虑滚动数组优化。
  2. 单调队列优化是处理区间最小值转移的常用技巧，需要熟练掌握。

F. 今晚吃流年（AC，罚时 104 min）

解题思路：将每个 CP 对 (x, y)（x < y）视为一个约束。需要找到 a₁、a₂ 使得所有 CP 对都跨越两个性别区域。可以预处理前缀/后缀信息，然后枚举分界点判断。

  • 提交 #12（AC）：增加了一个 f 数组记录后缀中最小的左端点，修正了输出逻辑。

经验教训：构造题需要仔细验证输出方案的合法性。在枚举分界点时，不仅要判断是否存在解，还要确保输出的解确实满足所有约束。

解题思路：使用带权并查集维护变量之间的关系。每个变量表示为 a_i * x + b_i 的形式（其中 x 是某个代表元），合并时维护系数和常数。如果两个变量已经在同一集合中，检查是否矛盾；否则合并两个集合。

D. 今晚吃转转（AC，罚时 109 min）

知识点：树哈希、树的同构、中心/重心、旋转对称

难度预估：中等偏难

题目分析：给定一棵树，判断对于哪些正整数 k，可以将其绘制在平面上并绕某点旋转 2π/k 后与原图重合。

解题思路：

  • 将树压缩（去掉度为 2 的点），得到简化树。
  • 找到简化树的中心（可能是一个点或一条边）。
  • 如果中心是一个点，则 k 的取值由该点各分支的哈希值分组决定——每组相同哈希值的分支数量必须能被 k 整除。
  • 如果中心是一条边，则 k = 1 一定可行，k = 2 当且仅当两侧子树同构。

提交记录分析：一次 AC。代码使用了树哈希（随机化哈希）来判断子树同构，并利用 unordered_map 统计分组。

经验教训：树哈希是判断树同构的常用技巧，需要熟练掌握。本题的难点在于将几何旋转问题转化为树的对称性问题，需要较强的抽象思维能力。

C. 今晚吃春天（AC，罚时 262 min）

知识点：状态压缩 DP、博弈论、贪心、牌型判断

难度预估：困难

题目分析：四人斗地主中，地主需要判断是否能保证打出"春天"（农民一张牌都出不了）。给定地主的 33 张牌，需要判断是否存在一种出牌策略，使得无论农民如何分牌，农民都无法接牌。

解题思路：核心思路是：地主需要找到一种出牌顺序，使得每次出牌都是"不可被接"的。具体地：

  • 如果地主能一次出完所有牌，则一定可以春天。
  • 否则，地主需要先出"炸弹"或"王炸"等不可被接的牌型，然后再出完剩余牌。
  • 对于剩余牌，需要判断是否能组成一个合法的"飞机"（三顺 + 对子）或"炸弹"等牌型。

提交记录分析（7 次错误提交）：

  • 提交 #23-28（WA）：多次尝试不同的牌型判断逻辑，但都存在漏洞。主要问题在于：

    1. 对"飞机"牌型的判断不完整，没有考虑所有可能的对子组合。
    2. 对"王炸"的处理有误，没有正确判断王炸是否在手中。
    3. 对剩余牌的判断逻辑不完整。

  • 提交 #32-33（WA）：继续调整飞机牌型的判断逻辑，但仍有问题。

  • 提交 #45（AC）：最终修正了飞机牌型的判断逻辑，特别是：

    1. 正确处理了王炸（4 张王）的情况。
    2. 修正了飞机中三顺部分的循环范围（l 从 1 到 13，r 从 l 到 13，但 r=13 时 l 必须等于 13）。
    3. 修正了对子部分的 DP 转移逻辑。

关键问题分析：

  1. 飞机牌型的判断：飞机 = 连续的三顺 + 若干对子。三顺部分需要连续，对子部分可以任意选择（包括重复点数）。代码中使用 DP 判断是否能从剩余牌中选出足够的对子。

  2. 边界条件：三顺的右端点不能超过 13（即不能包含 2），但左端点可以到 1。同时，如果三顺包含 13（即 2），则只能单独出。

经验教训：

  1. 复杂规则题需要仔细阅读题面，确保理解所有边界条件。
  2. 牌型判断类题目需要系统性地枚举所有可能情况，避免遗漏。

  • 实现复杂度高：需要精细的代码实现和调试能力。
  • 思维难度大：需要将字符串子串关系转化为 AC 自动机上的树结构问题。

补题建议：仔细研究 AC 自动机 fail 树的性质，理解如何将"子串"关系转化为树上的祖先-后代关系。同时学习分块数据结构在 DP 优化中的应用。

推荐：C. 今晚吃春天

推荐理由：

  • 规则复杂：需要仔细理解斗地主的所有牌型和比较规则。
  • 思维巧妙：将"保证春天"转化为"存在一种出牌顺序使得所有牌型不可被接"。
  • 实现细节多：需要处理各种边界情况。

补题建议：重点理解飞机牌型的判断逻辑，以及如何用 DP 判断是否能从剩余牌中选出足够的对子。

推荐：D. 今晚吃转转

推荐理由：

  • 几何与树的结合：将旋转对称问题转化为树的同构问题。
  • 树哈希的应用：是判断树同构的经典技巧。
  • 思维难度适中：需要一定的抽象能力。

补题建议：学习树哈希的实现方法，理解如何判断树的分支是否同构。

  1. A 题投入时间过多：A 题从 16:06 到 17:38 共耗时 92 分钟，期间经历了 8 次错误提交。虽然最终 AC，但消耗了大量时间。建议在多次失败后，暂时放下题目，先做其他题目，让大脑休息一下再回来。

4.3 可执行的改进项

  1. 建立模板库：将常用的数据结构（如带权并查集、树哈希、AC 自动机等）整理成模板，比赛中直接调用。

  2. 练习滚动数组：在平时的训练中，养成使用滚动数组的习惯，避免 MLE。

  3. 加强边界条件测试：在提交前，使用小数据、边界数据（如 n=1、n=2、全 0、全 1 等）进行测试。

  4. 团队分工优化：在比赛后期，可以安排一名队员专门负责调试，另一名队员思考新题，第三名队员准备提交。
