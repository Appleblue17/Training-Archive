B. 今晚吃……（AC，12:15，1 WA）

  • 知识点：动态规划、状态压缩、字符串子序列
  • 预估难度：签到题（Div.2 A/B）
  • 最终罚时：12:15 + 20min = 12:35

题目分析：

给定 01 字符串 s s s，需要找到一个最短子序列 s s u b s_{sub} ssub​，使得 s s u b s_{sub} ssub​ 中出现的所有长度为 2 的子串集合与 s s s 中出现的所有长度为 2 的子串集合完全相同。全集为 {00, 01, 10, 11} 共 4 种，用 4 位二进制掩码表示。

解题思路：

动态规划。设 dp[t][i][mac] 表示考虑到原串第 t t t 个字符，子序列最后一个字符为 i i i（0 或 1），已经覆盖的二元子串集合为 mac 时的最短子序列长度。转移时，要么跳过当前字符，要么将当前字符接在子序列末尾（此时新增一个二元子串 (last, current)）。最终答案为 dp[n][0/1][full_mask] 的最小值。

错误分析（提交 #1）：

第一次提交的 WA 出现在状态转移的核心代码：

// 错误版本
gmin(dp[t+1][c][mac | nmac], x+1);
// 其中 nmac = (1 << (b + c*2))，b = a[t]

// 正确版本
gmin(dp[t+1][c][mac | (1 << (i + c*2))], x+1);

错误在于：nmac 使用的是 a[t]（原串第 t t t 个字符）而非 i（当前子序列的最后一个字符）。当子序列跳过了原串中的某些字符时，子序列的最后一个字符并不一定是 a[t]，因此新增的二元子串应该是 (i, c) 而非 (a[t], c)。

关键转折点：

这是一个非常典型的 DP 状态设计错误——状态中记录了子序列最后一个字符 i，但在转移时却忘记使用这个状态变量，而是错误地使用了原串的字符。这类错误在 DP 中很常见，提醒我们在转移时务必确认使用的是状态变量而非原始输入数据。

经验总结：

  • 这道题从提交到修正仅用了 4 分钟，说明队伍调试效率很高。
  • 错误原因非常典型：状态变量与原始数据混淆。建议在写 DP 转移时，明确标注哪些变量来自状态、哪些来自输入。

H. 今晚吃 NPC（AC，12:21，0 WA）

  • 知识点：位运算、构造
  • 预估难度：签到题（Div.2 A）
  • 最终罚时：12:21

题目分析：

给定一个由 &、^、| 组成的表达式 x 1   o p 1   x 2   o p 2   ⋯   o p n − 1   x n = w x_1\ op_1\ x_2\ op_2\ \cdots\ op_{n-1}\ x_n = w x1​ op1​ x2​ op2​ ⋯ opn−1​ xn​=w，需要构造一组非负整数解。

解题思路：

关键观察：由于三个运算符的优先级是 & > ^ > |，我们可以利用全 1（0x7FFFFFFF）和全 0 来"屏蔽"不需要的项。

构造方法：

  • 令 x 1 = w x_1 = w x1​=w。
  • 对于 i ≥ 2 i \geq 2 i≥2：
    • 如果 o p i − 1 op_{i-1} opi−1​ 是 | 或 ^，令 x i = 0 x_i = 0 xi​=0。因为 y   ∣   0 = y y\ |\ 0 = y y ∣ 0=y， y  xor  0 = y y\ \text{xor}\ 0 = y y xor 0=y，不会改变结果。
    • 如果 o p i − 1 op_{i-1} opi−1​ 是 &，令 x i = 0 x 7 F F F F F F F x_i = 0x7FFFFFFF xi​=0x7FFFFFFF（全 1）。因为 y   &   111 … = y y\ \&\ 111\ldots = y y & 111…=y，不会改变结果。

这样构造可以保证无论运算符优先级如何，最终结果都等于 w w w。

经验总结：

  • 这是一道非常巧妙的构造题，核心思想是利用 0 和全 1 作为"单位元"来屏蔽运算。
  • 一次通过，说明队伍对位运算的性质掌握扎实。
  • 注意代码中 ans[1] = w 的构造方式，实际上 x 1 x_1 x1​ 取 w w w 即可，不需要额外处理。

L. 今晚吃 TopTree（AC，12:42，0 WA）

  • 知识点：贪心、树形 DP、优先队列/堆
  • 预估难度：中等偏易（Div.2 C）
  • 最终罚时：12:42

题目分析：

给定一棵有根树，允许通过新建节点将任意两个兄弟子树合并，目标是使最终树满足每个节点至多两个儿子。需要分别最小化：

  1. 最终树的高度；
  2. 所有原始节点的深度之和。

解题思路：

这是一个典型的"哈夫曼合并"问题。对于每个节点 u u u，假设它有 k k k 个儿子，每个儿子对应一棵子树。我们需要通过合并操作将这 k k k 棵子树组织成一棵二叉树。

  • 最小化高度：每次选择深度最小的两棵子树合并（类似 Huffman 树的思想），使得合并后的深度增加尽量小。用优先队列维护子树深度，每次弹出最小的两个合并后压回。
  • 最小化深度和：每次选择子树大小最小的两棵合并（类似 Huffman 编码），因为合并时，被合并的两棵子树中所有节点的深度都会 +1，所以优先合并小的子树可以最小化总深度增加量。

代码亮点：

// 最小化深度和：按子树大小贪心合并
while(s.size()>1){
    int v = s.top(); s.pop();
    int w = s.top(); s.pop();
    sm[u] += -v-w;  // 合并后所有节点深度+1
    s.push(v+w);
}

经验总结：

  • 一次通过，说明队伍对 Huffman 合并类问题非常熟悉。
  • 两个最小值的计算相互独立，可以分别用不同的贪心策略，这一点在题目中已经明确提示。
  • 注意 priority_queue 默认是大根堆，代码中使用取负的方式实现小根堆，是常见技巧。

I. 今晚吃草莓（AC，13:30，1 MLE）

  • 知识点：动态规划、单调队列优化、滚动数组
  • 预估难度：中等（Div.2 D）
  • 最终罚时：13:30 + 20min = 13:50

题目分析：

白井黑子从起点 s s s 出发，依次进行 m m m 次冲刺。每次冲刺可以选择位移 d i ∈ [ − k i , k i ] d_i \in [-k_i, k_i] di​∈[−ki​,ki​]，若 ∣ d i ∣ = k i |d_i| = k_i ∣di​∣=ki​ 或撞墙则获得 c i c_i ci​ 颗草莓。对于每个终点 t t t，在草莓总数不超过 K t K_t Kt​ 的前提下，最大化撞墙次数。

解题思路：

三维 DP：dp[i][j][k] 表示前 i i i 次冲刺后位于位置 j j j，撞墙 k k k 次的最小草莓数。转移分为三类：

  1. 普通移动：从位置 j ′ j' j′ 移动到 j j j，满足 ∣ j − j ′ ∣ < k i |j - j'| < k_i ∣j−j′∣<ki​（不撞墙），用单调队列优化区间最小值。
  2. 撞左墙：从位置 j ′ ∈ [ 1 , k i − 1 ] j' \in [1, k_i-1] j′∈[1,ki​−1] 移动到位置 1，撞墙一次。
  3. 撞右墙：从位置 j ′ ∈ [ n − k i + 2 , n ] j' \in [n-k_i+2, n] j′∈[n−ki​+2,n] 移动到位置 n n n，撞墙一次。
  4. 极限位移： ∣ d i ∣ = k i |d_i| = k_i ∣di​∣=ki​ 时也获得草莓，需要特殊处理（代码中通过枚举 t = − K [ i ] t = -K[i] t=−K[i] 和 t = K [ i ] t = K[i] t=K[i] 实现）。

错误分析（提交 #9）：

第一次提交 MLE，原因是使用了 dp[N][N][N] 三维数组（ N = 550 N = 550 N=550），内存占用约 550 3 × 8 550^3 \times 8 5503×8 字节 ≈ 1.3GB，远超限制。

// 错误版本：三维数组
int dp[N][N][N];  // 550 * 550 * 550 * 8B ≈ 1.3GB

// 正确版本：滚动数组
int dp[2][N][N];  // 2 * 550 * 550 * 8B ≈ 4.8MB

关键转折点：

MLE 后立即改为滚动数组，将第一维从 m m m 压缩到 2，内存从 1.3GB 降至约 5MB，同时时间复杂度不变。这是一个非常标准的优化手段，队伍在 4 分钟内完成了修改并 AC。

经验总结：

  • 在写 DP 之前，应该先估算内存。 n , m ≤ 500 n, m \leq 500 n,m≤500 时， O ( n m 2 ) O(nm^2) O(nm2) 的 DP 如果用三维数组存储很容易 MLE。
  • 滚动数组是 DP 内存优化的第一选择，当转移只依赖上一层时应当立即使用。
  • 单调队列优化区间最小值是 DP 优化的常用技巧，本题中用于优化普通移动的转移。

F. 今晚吃流年（AC，13:44，1 WA）

  • 知识点：图论、二分图判定、前缀/后缀最值
  • 预估难度：中等（Div.2 C/D）
  • 最终罚时：13:44 + 20min = 14:04

题目分析：

给定 n n n 个学生和 m m m 对 CP 关系（每对必须是异性），已知性别分布为：存在 1 < a 1 < a 2 < n + 1 1 < a_1 < a_2 < n+1 1<a1​<a2​<n+1，使得 [ 1 , a 1 − 1 ] ∪ [ a 2 , n ] [1, a_1-1] \cup [a_2, n] [1,a1​−1]∪[a2​,n] 为一种性别， [ a 1 , a 2 − 1 ] [a_1, a_2-1] [a1​,a2​−1] 为另一种性别。需要判断是否存在满足所有 CP 关系的 ( a 1 , a 2 ) (a_1, a_2) (a1​,a2​)。

解题思路：

将 CP 关系视为图中的边，问题等价于判断是否存在一种"两段式"的二分图染色方案。

关键观察：性别分布是"两段式"的——前一段和后一段同色，中间一段异色。因此可以枚举分界点，用前缀/后缀信息快速判断。

具体做法：

  • 预处理前缀数组 a[i]、b[i]、e[i]：分别表示前 i i i 个点中，所有边的最小右端点、最大左端点、最大右端点。
  • 预处理后缀数组 c[i]、d[i]、f[i]：分别表示从 i i i 到 n n n 中，所有边的最小右端点、最大左端点、最小左端点。
  • 枚举第一个分界点 i i i，检查是否存在合法的第二个分界点。

错误分析（提交 #11）：

第一次 WA 在输出答案时使用了 min(a[i], d[i+1]) 作为 a 1 a_1 a1​，但 a[i] 和 d[i+1] 分别来自前缀和后缀，取最小值并不能保证正确性。正确做法是使用 min(a[i], f[i+1])，其中 f[i+1] 是后缀中所有边的最小左端点。

// 错误版本
printf("%d %d\n", min(a[i], d[i+1]), c[i+1]);

// 正确版本
printf("%d %d\n", min(a[i], f[i+1]), c[i+1]);

经验总结：

  • 这道题的 WA 原因是在多个候选值中选择了错误的组合方式。在输出构造方案时，需要仔细验证每个值是否满足所有约束条件。
  • 前缀/后缀预处理是处理区间约束问题的常用技巧，本题中通过预处理将 O ( n m ) O(nm) O(nm) 的暴力优化为 O ( n + m ) O(n+m) O(n+m)。

D. 今晚吃转转（AC，14:49，0 WA）

  • 知识点：树哈希、树的重心、旋转对称性、树的同构
  • 预估难度：中等偏难（Div.2 D/E）
  • 最终罚时：14:49

题目分析：

给定一棵无根树，问存在哪些正整数 k k k，使得可以将树绘制在平面上，使其绕某个点旋转 2 π / k 2\pi/k 2π/k 后与原图像完全重合。

解题思路：

关键观察：如果一棵树绕某个点旋转 2 π / k 2\pi/k 2π/k 后与自身重合，那么旋转中心必须是树的重心（或边的中点）。进一步分析：

  1. k = 1 k = 1 k=1：任何树都满足（旋转 2 π 2\pi 2π 等于不旋转）。
  2. k = 2 k = 2 k=2：树必须关于某个点或某条边的中点中心对称。等价于树的重心两侧子树同构。
  3. k ≥ 3 k \geq 3 k≥3：树必须有一个"中心点"，且该点的所有子树可以分成若干组，每组大小相同且组内子树同构。 k k k 必须是某个分组大小的因子。

实现上：

  • 先找到树的重心（可能 1 个或 2 个）。
  • 用树哈希判断子树同构。
  • 对重心周围的子树分组，计算组大小的最大公约数， k k k 必须是该公约数的因子。

代码亮点：

// 树哈希
ull has[N];
void dfs(int u, int fa) {
    has[u] = 1;
    for (int v : G[u]) {
        if (v == fa) continue;
        dfs(v, u);
        has[u] += shift(has[v]);
    }
}

经验总结：

  • 一次通过，说明队伍对树哈希和重心的应用非常熟练。
  • 这道题的难点在于将几何旋转问题转化为树的对称性问题，需要较强的抽象能力。
  • 注意处理重心有两个的情况（此时 k k k 只能是 1 或 2）。

  • 预估难度：困难（Div.1 B/C）
  • 最终罚时：17:38 + 60min = 18:38

题目分析：

给定 n n n 个字符串 s 1 , s 2 , … , s n s_1, s_2, \ldots, s_n s1​,s2​,…,sn​（长度单调不降，两两不同），需要对于每个 k = 0 , 1 , … , n − 1 k = 0, 1, \ldots, n-1 k=0,1,…,n−1，计算恰好有 k k k 个字符串是"伪装"的方案数。要求剩余的字符串满足：每个字符串都是上一个字符串的子串。

解题思路：

将问题转化为：选择若干字符串作为"参赛选手"，使得它们构成一个链（每个是下一个的子串），其余为伪装。等价于在 AC 自动机上做 DP。

具体做法：

  • 将所有字符串插入 AC 自动机。
  • 对 AC 自动机的 fail 树进行树链剖分。
  • 按顺序处理每个字符串，用分块数据结构维护 DP 转移。

错误分析：

这道题经历了 3 次 TLE 和 1 次 RE，主要问题在于：

  1. TLE（提交 #20、#21、#22）：算法复杂度不够优化。核心问题在于 fnd 函数（查找最近标记祖先）的复杂度退化。每次调用 fnd 需要沿着 fail 树向上跳，最坏情况下 O ( n ) O(n) O(n)，导致总复杂度 O ( n 2 ) O(n^2) O(n2)。

  2. RE（提交 #30）：在 assert(ful[p]==1) 处触发，说明 AC 自动机上某个节点不是任何字符串的终点，但代码假设它是。这可能是由于 AC 自动机的转移边指向了非终点节点。

关键转折点：

  • 16:06 首次提交 TLE 后，队伍尝试了多种优化：
    • 限制 lim 的大小（提交 #21）
    • 增加剪枝条件（提交 #22）
    • 压缩 dfn 区间（提交 #25）
  • 最终在提交 #30 中改为使用 ed[p] 记录子树区间，并修正了 fnd 的实现，但触发了 RE。
  • 最终 AC 的版本（提交 #30 之后）应该是修复了 RE 问题。

经验总结：

  • 这道题是典型的"AC 自动机 + 树链剖分 + 分块"综合题，难度较高。
  • 多次 TLE 说明在实现复杂数据结构时，需要仔细分析每个操作的复杂度，避免最坏情况退化。
  • fnd 函数的实现是性能瓶颈，需要保证均摊复杂度。

C. 今晚吃春天（AC，17:42，5 WA）

  • 知识点：模拟、枚举、贪心、状态压缩 DP
  • 预估难度：中等偏难（Div.2 D/E）
  • 最终罚时：17:42 + 100min = 19:22

题目分析：

四人斗地主中，地主有 33 张牌，需要判断是否存在一种出牌策略，使得无论农民如何分牌，地主都能"春天"（农民一张牌都打不出）。

解题思路：

核心观察：地主需要连续出牌直到出完，且农民无法接牌。因此地主的所有出牌必须构成一个"不可被接"的序列。

关键条件：对于地主出的每一手牌，农民手中必须没有任何能大过它的牌。由于农民共有 75 张牌（每种点数 8 张减去地主手中的），地主需要保证自己出的牌足够大。

具体做法：

  • 枚举地主的第一手牌（可以是炸弹、顺子、连对、钢板、飞机等）。
  • 对于剩余的牌，检查是否可以一次性出完（作为炸弹或飞机等）。
  • 需要计算每种点数农民手中可能的最大数量，确保地主出的牌不会被接。

错误分析：

C 题经历了 5 次 WA，主要问题集中在 checksc 函数（检查飞机牌型）的边界条件：

  1. 提交 #23：checksc 中 c[14] + c[15] == 2 时，错误地假设 t[14][1] = 1，但未考虑 c[14] 和 c[15] 的具体分布。
  2. 提交 #24：修复了 c[i] < 0 的检查，但 c[14] + c[15] == 2 的处理仍有问题。
  3. 提交 #26：增加了 c[14] == 1 || c[15] == 1 的检查，但仍不完整。
  4. 提交 #27：修改了 c[14] + c[15] == 2 的条件为 c[14] != c[15]，但逻辑仍有漏洞。
  5. 提交 #28：最终修复了所有边界条件。

经验总结：

  • 这道题的难点在于对斗地主规则的理解和边界条件的处理。
  • 5 次 WA 说明在复杂模拟题中，需要系统性地列出所有边界情况，而不是每次只修补一个漏洞。
  • 建议在写模拟题时，先画出完整的决策树或状态转移图，再开始编码。

J. 今晚吃黑子（未通过，1 WA）

  • 知识点：组合数学、DP、字符串
  • 预估难度：困难（Div.1 B/C）
  • 最终罚时：无（未 AC）

题目分析：

给定一个 01 字符串，每次操作可以选择一个位置 i i i（ 1 < i < n 1 < i < n 1<i<n），如果 i − 1 i-1 i−1 和 i + 1 i+1 i+1 处的字符不同，则删除这两个字符。求最终可能得到的字符串数量。

解题思路：

这道题需要深入分析操作的性质。每次操作删除两个相邻的异色字符（中间隔一个字符），相当于在字符串中不断删除"010"或"101"模式的左右两端。

关键观察：操作的本质是删除一对异色字符，且这两个字符之间恰好隔一个字符。可以转化为某种匹配问题。

错误分析：

提交 #29 的代码尝试用 DP 解决，但状态设计可能不够完整。代码中定义了 ch0[i] 和 ch1[i] 表示从位置 i i i 出发的转移，但转移条件可能遗漏了一些情况。

经验总结：

  • 这道题难度较高，队伍在 16:59 才首次提交，说明思考时间较长但未能形成完整思路。
  • 对于这种操作类问题，建议先在小数据上暴力模拟，找出规律后再设计算法。

G. 今晚吃老歌（未通过，无提交）

  • 知识点：数据结构、区间覆盖、可重集维护
  • 预估难度：困难（Div.1 C/D）
  • 最终罚时：无

题目分析：

维护一个区间可重集合，支持插入、删除、查询"恰好被一个区间覆盖的点数"。

解题思路：

需要一种支持区间加/减和查询"恰好为 1"的数据结构。可以考虑使用线段树维护每个点被覆盖的次数，查询时统计次数为 1 的点的数量。但操作 3 要求只考虑完全落在查询区间内的区间，这增加了难度。

经验总结：

  • 从数据范围（ n , q ≤ 5 × 10 5 n, q \leq 5 \times 10^5 n,q≤5×105）来看，需要 O ( ( n + q ) log ⁡ n ) O((n+q)\log n) O((n+q)logn) 的算法，且需要支持可重集的插入删除。

三、补题推荐

强烈推荐：A. 今晚吃什么

  2. 实现难度高：需要精细的常数优化和内存管理，对代码能力要求很高。

补题建议：

  • 重点学习 fnd 函数的实现，理解如何利用树链剖分快速查找最近标记祖先。
  • 尝试用不同的分块大小（ B = 330 B = 330 B=330 vs B = 450 B = 450 B=450）对比性能。

推荐：C. 今晚吃春天

补题建议：

  • 先仔细阅读题目，列出所有合法牌型和比较规则。

  1. A 题投入时间过晚：A 题作为困难题，直到 16:06 才首次提交，说明前期没有投入足够时间思考。建议在中期（通过 5-6 题后）就开始思考困难题，而不是等到后期。

4.3 团队协作建议

  1. 分工明确：建议在比赛开始前明确分工，如一人负责签到题、一人负责中期题、一人负责后期难题。本场比赛中 B、H、L 三题在 42 分钟内连续 AC，说明前期分工执行得很好。

  2. 并行思考：在一个人编码时，其他人应阅读其他题目并思考思路。本场比赛中 D 题在 14:49 AC，说明有人在前期就开始思考这道题。

  3. 代码审查：在提交前，让队友快速审查代码，特别是边界条件和状态转移。本场比赛中 B 题的 WA 如果经过审查，可能可以避免。

本场比赛展现了队伍扎实的基础功底和良好的抗压能力，9 题的成绩在强对抗中值得肯定；但 A 题和 C 题的多次错误提交提醒我们，在复杂题目的边界处理和数据结构实现上仍需精益求精——细节决定成败，愿你们在后续比赛中继续保持开局锐气，同时用更严谨的验证换取更低的罚时。
